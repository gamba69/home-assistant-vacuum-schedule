# Vacuum Schedule

Vacuum Schedule — пользовательская интеграция Home Assistant для детерминированного расписания робота-пылесоса, pre-flight проверок, WAIT, Dry-Run/REAL выполнения, уведомлений, обслуживания, статистики и прогнозирования.

## Публичное имя с 0.13.0

- Название: **Vacuum Schedule**
- Domain: `vacuum_schedule`
- Каталог интеграции: `custom_components/vacuum_schedule/`
- Репозиторий: `gamba69/home-assistant-vacuum-schedule`
- Actions/services Home Assistant: `vacuum_schedule.*`
- Путь панели: `/vacuum-schedule`

Прежнее публичное имя `vacuum_scheduler` считается legacy и используется только кодом одноразовой миграции 0.12.61 → 0.13.0.

## Установка

Для новой установки скопируйте `custom_components/vacuum_schedule/` в каталог `custom_components` Home Assistant и перезапустите Home Assistant. Структура репозитория подготовлена для добавления как custom repository HACS.

При обновлении с 0.12.61 установите 0.13.3, перезапустите Home Assistant, добавьте **Vacuum Schedule**, выберите тот же пылесос и подтвердите миграцию найденной legacy-записи.

## Текущая модель

- **Schedule** задаёт повторяющиеся локальные occurrence и корректировки по дням недели.
- Материализованный **JobInstance** представляет конкретный occurrence и хранит его жизненный цикл.
- Зоны уборки связывают логическую зону планировщика с физической целью робота и содержат правила занятости/доступности и номинальную площадь.
- Pre-flight и WAIT отделены от физического выполнения. Исправимый blocker не расходует occurrence до границы command-intent.
- Dry-Run проходит логику scheduler/pre-flight/уведомлений без физических команд и без обучения REAL-статистики.
- Statistics Ledger и модели прогнозов хранятся независимо от Home Assistant Recorder.
- Внешние физические запуски сохраняются, но обучают модель только при надёжной привязке цели и профиля.
- Прогнозирование строго разделено по эффективному профилю уборки; история другой конфигурации той же зоны не подмешивается ради получения оценки.

## Ручные и автоматические запуски

- **Дополнительный запуск** создаёт отдельный manual Job и не расходует следующий плановый occurrence.
- **Запустить раньше вручную** выполняет уже существующий будущий occurrence и сохраняет его исходный эффективный профиль.
- **Смарт-запуск** выполняет ещё не использованный плановый occurrence текущего локального дня, а при его отсутствии создаёт дополнительный запуск.
- Runtime-команды доступны как actions Home Assistant в namespace `vacuum_schedule.*`.

## Локализация

Начиная с базовой версии 0.12.61 документация проекта синхронно ведётся на **английском, русском и украинском**. Интеграция Home Assistant и собственная панель также поставляют EN/RU/UK локализацию.
