# История изменений

## 0.13.2

- Исправлен порядок ключей `manifest.json` по требованиям hassfest.
- `*.patch` добавлен в `.gitignore`; случайно попавший в репозиторий патч 0.13.1 удалён.
- Добавлен GitHub Actions workflow полного проектного тестирования: regression suite, компиляция Python, проверка синтаксиса frontend JavaScript, JSON/YAML и запрет закоммиченных patch-файлов для `main`, pull request, тегов версий и опубликованных релизов.
- GitHub checkout actions обновлены на версию на базе Node 24.
- Версия интеграции и frontend cache/component identity подняты до 0.13.2.
- Проверка релиза: **989 тестов успешно**, Python compile, синтаксис frontend JavaScript и JSON/YAML прошли проверку.

## 0.13.1

- Исправлена HACS/hassfest-валидация нового репозитория.
- В manifest объявлена зависимость Home Assistant `http`, используемая для static path собственной панели.
- Интеграция явно объявлена config-entry-only для проверки YAML schema.
- Ключи переводимых состояний сенсора приведены к допустимому lowercase без изменения внутренних результатов Job.
- Некорректный selector sentinel заменён на допустимое значение с сохранением совместимости со старыми сохранёнными расписаниями.
- Добавлена лицензия репозитория и удалены устаревшие ссылки на отдельный migration-документ из README.
- Frontend component/cache identity поднят до 0.13.1.

## 0.13.0

- Интеграция переименована в **Vacuum Schedule**.
- Публичный domain изменён на `vacuum_schedule`, каталог — на `custom_components/vacuum_schedule/`.
- Namespace actions/services Home Assistant изменён на `vacuum_schedule.*`.
- Путь панели изменён на `/vacuum-schedule`; frontend storage, events и WebSocket-команды переведены на новую публичную идентичность.
- Добавлена одноразовая миграция legacy-domain 0.12.61: data/options config entry и все собственные persistent Store, включая месячные chunks Statistics Ledger.
- Отдельные файлы patch-notes по каждой версии удалены навсегда; история релизов ведётся только в синхронном changelog/документации.
- Введено обязательное синхронное ведение документации проекта на английском, русском и украинском.
- Добавлена миграция локальных архивов резервных копий статистики в новый namespace `vacuum_schedule_backups/` и новый config-entry id.
- Проверка релиза: **983 теста успешно**, Python compile, синтаксис JavaScript, JSON и YAML — OK.
- Репозиторий подготовлен для HACS: добавлены `hacs.json`, hassfest и HACS validation workflows.
- Функциональная логика scheduler/statistics/forecast остаётся на базе 0.12.61; 0.13.0 посвящён релизному переименованию, миграции и документации.

## 0.12.61 — базовая версия

- Исправлен опасный Forecast fallback, который смешивал разные профили уборки только из-за совпадения зон.
- Прогнозы времени и аккумулятора требуют достаточного числа наблюдений точного эффективного профиля: целого Job либо same-profile композита зон.
- Исторические dry/mop-only подписи канонизируются: неактуальные поля не дробят один физический профиль, отсутствующие `passes` нормализуются в `1×`.
- В таблице «Оценка» недостаточная история точного профиля показывается явно вместо заимствованной оценки по той же зоне.
- Базовая regression suite: **974 теста успешно**.
