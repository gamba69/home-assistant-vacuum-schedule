# 0.14.0 — Optional mains power monitoring

Configure **Scheduler settings → Schedule execution → Power supply monitoring**. Monitoring is disabled for all existing installations after upgrade. Select a Home Assistant binary sensor and specify whether `on` or `off` means that external power is present. The selection and polarity are stored in integration options; no hardcoded entities or hidden defaults are used.

When power is missing, scheduled, early and manually released jobs remain in `WAIT` with `power_supply_unavailable`, subject to their existing deadlines. An `unknown` or `unavailable` sensor also blocks new starts (`power_supply_unknown`), but does not itself trigger an emergency stop. Power restoration re-evaluates jobs immediately; it never resumes an interrupted cleaning session. The physical start path checks live mains status after parameter preparation and again after writing command intent. Dry-Run never sends robot commands.

When **REAL** execution is selected, a confirmed outage during **any** robot cleaning (including runs started externally through the vendor app) triggers best-effort `vacuum.stop` followed by `vacuum.return_to_base`. These are commands, not guarantees that the robot physically stopped or reached its dock. Commands may fail when the dock, network or Home Assistant has lost power. The event is recorded as `power_supply_lost` for scheduler-owned and external sessions; already completed zones keep their results, and no further passes or zones start for the interrupted job. Confirmation is observation-driven, with a bounded confirmation timeout and explicit unconfirmed-stop metadata.

Power monitoring requires Home Assistant and communication with the robot to remain operational during an outage (typically via UPS). To test: toggle a **test** binary sensor while no cleaning is active and confirm `WAIT`/automatic recovery; then perform a controlled REAL test, including an external run. Never cut power to the robot or its dock merely to test the integration.
