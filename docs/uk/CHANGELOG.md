## 0.13.1

- Frontend component/cache identity піднято до 0.13.1.

## 0.13.0

- Інтеграцію перейменовано на **Vacuum Schedule**.
- Публічний domain змінено на `vacuum_schedule`, каталог — на `custom_components/vacuum_schedule/`.
- Namespace actions/services Home Assistant змінено на `vacuum_schedule.*`.
- Шлях панелі змінено на `/vacuum-schedule`; frontend storage, events і WebSocket-команди переведено на нову публічну ідентичність.
- Додано одноразову міграцію legacy-domain 0.12.61: data/options config entry та всі власні persistent Store, включно з місячними chunks Statistics Ledger.
- Окремі файли patch-notes для кожної версії видалено назавжди; історія релізів ведеться лише в синхронному changelog/документації.
- Запроваджено обов'язкове синхронне ведення документації проєкту англійською, російською та українською.
- Додано міграцію локальних архівів резервних копій статистики до нового namespace `vacuum_schedule_backups/` і нового config-entry id.
- Перевірка релізу: **983 тести успішно**, Python compile, синтаксис JavaScript, JSON і YAML — OK.
- Репозиторій підготовлено для HACS: додано `hacs.json`, hassfest і HACS validation workflows.
- Функціональна логіка scheduler/statistics/forecast залишається на базі 0.12.61; 0.13.0 присвячений релізному перейменуванню, міграції та документації.

## 0.12.61 — базова версія

- Виправлено небезпечний Forecast fallback, який змішував різні профілі прибирання лише через збіг зон.
- Прогнози часу й акумулятора потребують достатньої кількості спостережень точного ефективного профілю: цілого Job або same-profile композита зон.
- Історичні dry/mop-only підписи канонізуються: неактуальні поля не розділяють один фізичний профіль, відсутні `passes` нормалізуються у `1×`.
- У таблиці «Оцінка» недостатня історія точного профілю показується явно замість запозиченої оцінки для тієї самої зони.
- Базова regression suite: **974 тести успішно**.
