# Тестування та перевірка релізу

Кожен реліз перевіряється на чистому дереві та повторно після розпакування фінального архіву.

## Обов'язкові перевірки

```bash
pytest -q
python -m compileall -q custom_components tests
node --check custom_components/vacuum_schedule/frontend/panel.js
```

Додатково:

- розібрати кожен JSON-файл;
- переконатися, що `PATCH_*.md` відсутні;
- у `custom_components/` має бути рівно один каталог інтеграції — `vacuum_schedule`;
- `manifest.json` має містити `Vacuum Schedule`, `vacuum_schedule` і поточну версію;
- публічні actions мають використовувати `vacuum_schedule.*`;
- старий рядок `vacuum_scheduler` дозволений лише в явному migration-коді/тестах/документації;
- перевірити однаковий набір файлів документації EN/RU/UK;
- перевірити однаковий набір translation keys EN/RU/UK для Home Assistant;
- виключити кеші та `*.pyc` з релізних архівів.

## Regression міграції 0.13.0

Тести мають підтверджувати перенесення кожного власного Store версії 0.12.61, виявлення місячних Statistics Ledger chunks за старим індексом, створення нового запису з копією `data` та `options`, а також видалення старої config entry лише після успішного копіювання даних.

## Базова точка

0.12.61: 974 тести успішно. У 0.13.0 ця база зберігається та доповнюється контрактами перейменування, тримовної документації й legacy-data migration.
